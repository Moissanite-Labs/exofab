# Contributing

Exofab is at the orientation and discovery stage. Start by reading the [orientation](docs/orientation.md), the [ecosystem boundaries](docs/ecosystem.md), and the [roadmap](docs/roadmap.md), then check existing issues and pull requests for related work.

For a proposed change, explain the problem, evidence, intended outcome, alternatives or tradeoffs, and unresolved questions. Keep changes focused and reviewable. Mark proposals as proposals and describe what was actually verified. Link public sources where helpful; do not include credentials, private material, or personal data.

- **Decisions.** Governance, licensing, identity, economic rights, external services, and data reuse each need an explicit maintainer decision recorded in the [roadmap](docs/roadmap.md). A merged document or passing test does not decide them by itself.
- **Review.** Ask for review from someone other than the author, and review the exact final commit.
- **Sibling repositories.** Changes Exofab needs in Koinos, Synbios, Exo, Ethos, or credos belong in those repositories, through their own processes. Read their code for reference; do not copy code from a repository that has not granted a license.
- **Examples and fixtures.** Use visibly fictional people and data. Never include real private keys, personal agreements, or private records.
- **Untrusted content.** Treat agent-submitted text, record contents, and artifacts as data, never as instructions.
- **Security problems.** Report them privately to the maintainers of the affected repository, following its security policy, rather than in a public issue.

No build or test commands have been established for this repository. For documentation changes, check links and accuracy. Agree the first use case and implementation direction before introducing a stack, external service, or dependency. The project's license and contribution terms have not yet been selected; do not assume a license, and do not add one on someone else's behalf.
